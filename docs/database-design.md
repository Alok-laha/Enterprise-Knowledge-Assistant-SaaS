# Initial identity and tenant schema

The API uses PostgreSQL and SQLAlchemy 2.x models. Alembic owns schema changes;
do not create these tables from application startup code.

## Tables

- `tenants`: UUID primary key, unique required name, a required category
  (`Start-up`, `Enterprise`, `Non-profit`, `Government`, `Mid-size`, or
  `Small Business`), and timezone-aware creation time. The category is stored as
  a string with a database check constraint.
- `users`: UUID primary key, Cognito `sub` (unique stable identity), email, and
  required name and timezone-aware creation time. Both the Cognito `sub` and
  email are unique; email is indexed to support lookups.

These tables are not directly related yet. When tenant membership is added,
represent the many-to-many association in a `memberships` table rather than
adding a single tenant ID to `users`.

## Migrations

From `services/api`, configure `DATABASE_URL` (or use the local `.env`) and run:

```bash
alembic upgrade head
```

After changing a model, create a revision with
`alembic revision --autogenerate -m "describe the schema change"`, review its
operations, and then apply it. Autogenerated revisions should always be
reviewed before use.

## Queries

Import `Tenant` or `User` from `app.models.tenant` or `app.models.user`, and
use a request-scoped SQLAlchemy session with `select()`:

```python
from sqlalchemy import select

tenant = db.scalar(select(Tenant).where(Tenant.id == tenant_id))
user = db.scalar(select(User).where(User.cognito_sub == cognito_sub))
```

When adding tenant-owned data, scope reads and writes to the authenticated
tenant context; do not trust a tenant ID supplied by the client.

## Tenant registration API

`POST /api/v1/tenants` creates a tenant from its name and category:

```json
{
  "name": "Acme",
  "type": "Start-up"
}
```

The endpoint responds with `201 Created` and the tenant record. It responds
with `409 Conflict` if a tenant with the same name already exists. This initial
endpoint does not yet authenticate or assign a tenant owner; add Cognito
authentication and a membership record before using it as a complete
multi-tenant onboarding flow.
